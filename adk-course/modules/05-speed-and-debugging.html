Speed, Cost and Debugging

Where the time and money go, the tricks that cut them, and how to find out what went wrong

Where the time goes: model calls

Every time an agent thinks or uses a tool, the model reads its whole prompt again. The amount of text it reads is measured in tokens. In one real A2 run, the SIEM and EDR specialists each read about 50,000 input tokens, mostly their own growing tool results.

🧹

No chat history

include_contents="none": each agent sees only its inputs, not everyone's earlier tool results.

🗜️

Compact tool results

No pretty-printing and no empty fields: about 40% fewer characters. At most 10 events per search.

✂️

Word limits

Schemas say "max 2 sentences", "max 4 findings". Shorter answers are faster answers.

⚙️

Plain-code Reporter

The ticket is a template, so one whole model call (the biggest output) is gone. 7,974 → 2,653 characters.

💤

Thinking off

Qwen normally "thinks" in hidden text before answering. VLLM_THINKING=off skips that.

The barista who already knows your order

A good barista starts your usual drink when you walk in. Model servers do the same with a prompt cache. If a prompt starts with exactly the same text as last time, that part is skipped. ADK always adds "Your internal name is…" to each agent's system prompt, though, so the start was different at every hand-off between agents.

CODE · soc_agents/common/callbacks.py 
def shared_system_prompt(callback_context, llm_request) -> None:
    """before_model_callback: move the agent-specific system text into the first user message."""
    config = llm_request.config
    own = config.system_instruction if config else None
    if isinstance(own, str) and own.strip() and own != SHARED_SYSTEM_PROMPT:
        from google.genai import types
        role = types.Content(role="user", parts=[types.Part(text="ROLE INSTRUCTIONS:\n" + own)])
        llm_request.contents = [role, *llm_request.contents]
        config.system_instruction = SHARED_SYSTEM_PROMPT
    return None

Gemini free tier vs your own server

Free Gemini is like a toll road with a daily pass: about 5 cars per minute and 20 per day for each model. One incident needs about 50 model calls, so it runs out fast. Your vLLM server has no pass to buy, but it's one road, so traffic jams happen.

⏱️
Gemini: 429 errors

The code waits and retries (up to 8 times). The daily limit can only be fixed by billing or switching to vLLM.

🚦
vLLM: at most 2 requests at once

Four specialists firing together caused a connect timeout. Now they queue for 2 slots and retry with growing pauses.

🔒
vLLM: data stays local

On the free Gemini tier Google may use your data, so only synthetic data belongs there.

When things break: read the flight recorder

Planes carry a black box that records everything. ADK's web UI has one too: the Events tab (every model call and tool call, in order) and the State tab (each agent's saved answer). Here are real bugs from this project and how they showed up.

1
Symptom: the run stops right after Triage

Events showed httpx.ConnectTimeout → four specialists overloaded vLLM → fix: concurrency limit and retries.

2
Symptom: "Validation Error … Input should be a valid list"

Qwen sent a list as text → the schema now accepts list-as-text instead of failing.

3
Symptom: typing "Approve" re-ran the whole investigation

Every message was treated as a new alert → plain-code Intake now handles commands.

4
Symptom: the policy blocked killing the malware

The target was written as "svchost-update.exe on WS-042" → the policy now finds the host inside the text.

💡
Give the AI the evidence, not your guess

When an agent run fails, copy the exact error and the last few Events into your request to the AI coding tool. "It stopped after triage" leads to guessing. "httpx.ConnectTimeout while 4 specialists ran in parallel" leads to the real fix in one step.
