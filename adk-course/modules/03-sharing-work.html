How Agents Share Work

Session state passes results between agents, and MCP tools let them read the security systems

Passing the baton: session state

Agents never talk to each other directly. They work like a relay race: each runner finishes their lap and hands a baton to the next. In ADK the baton is the session state.

Each agent's output_key says which label it writes. Here's what's on the notepad after one A2 run:

scenario"A2", written by Intake from the alert ID
triageSeverity, users, hosts, time window, questions for specialists
edr_findings · siem_findings · …One report per specialist, each citing event IDs
investigationVerdict, timeline, MITRE ATT&CK, compromised vs clean
response_planProposed actions, each marked allowed/blocked by policy
incident_report · incident_idThe ticket, and the ID used by the approval queue

How an agent reads the baton

A word in curly braces inside an agent's instructions is a placeholder. Just before the model reads its instructions, ADK swaps {triage} for Triage's actual answer.

Structured outputs make teamwork reliable

Because every agent must fill in a fixed form (its output_schema), the next agent always gets the same fields in the same place. When you design multi-agent systems, ask for "structured output with a schema" rather than free text.

Tools: one standard plug for every system

Agents reach the SIEM, EDR, AD, threat intel and case systems through MCP. Think of USB-C: one plug shape, any device. Each security system is a small MCP server exposing a few "lookups".

CODE · mcp_servers/siem_mcp.py 
    @read_tool(mcp)
    def get_alert(alert_id: str) -> dict:
        """Get one SIEM alert by id (e.g. ALR-A2-001), including entities, MITRE techniques and evidence event ids."""
        for a in store.alerts:
            if a["alert_id"].lower() == alert_id.lower():
                return a
        return {"error": f"alert {alert_id} not found"}
PLAIN ENGLISH

Register this as a read-only tool agents may call.

The tool is called get_alert and takes one input: an alert ID.

This description is what the model reads to decide when to use the tool, so it matters.

Go through every alert in the (fake) SIEM data…

…and if the ID matches (ignoring upper/lower case)…

…return that alert.

Otherwise say clearly that it wasn't found, never make one up.

Each agent only gets the plugs it needs. In mcp_tools("siem_mcp", ["get_alert", "get_events"]), the list is a tool filter. Triage can't search the SIEM in bulk, and no agent at all has a tool that changes anything.
