One Alert, Start to Finish

What this agent does for a bank's security team, and the journey of a single alarm through it

The job: a security team that never sleeps

Banks have a SOC. Every day it gets hundreds of alarms called alerts. Most are harmless. A few are real attacks, and a human analyst needs about an hour to dig into each one.

This project is a team of AI helpers that does that first hour of digging in a few minutes. It never touches a real system unless a human says yes.

🚨
Input: one alert

e.g. "Office application spawned encoded PowerShell on WS-042"

🔎
Work: AI agents investigate

They read logs, computer activity, account data and threat intelligence

📋
Output: verdict, plan and ticket

"Real attack, high severity. Here's what to block. Please approve."

🧪
It's a lab, not a real bank

Everything is fake: "Contoso Bank", its users and its attacks. The security tools are pretend versions that read from files, so you can experiment safely.

Think of a hospital emergency room

The word "triage" literally comes from the ER. When a patient arrives, a nurse decides how urgent it is, specialists run tests in parallel, a doctor makes the diagnosis, the patient signs consent, and only then is treatment given.

The very first line of code that runs

When you open the chat, the first thing that runs is not AI. It's a small piece of normal code called Intake. It reads your message and decides what to do with it.

CODE · soc_agents/intake.py 
if m := ALERT_RE.search(text):
    alert_id = m.group(0).upper()
    handled = state.get("handled_alerts") or {}
    if alert_id in handled and not re.search(r"\b(rerun|re-run|again)\b", text, re.I):
        return _reply(f"`{alert_id}` was already investigated in this session (incident `{handled[alert_id]}`).\n\n"
                      f"{_queue_table(handled[alert_id])}\n\nSay `rerun {alert_id}` to investigate it again.")
    scenario = alert_id.split("-")[1]
    if not _scenario_exists(scenario):
        return _reply(f"Unknown alert `{alert_id}`: no scenario `{scenario}` in the lab data.")
    state["current_alert"] = alert_id
    state["scenario"] = scenario  # every tool call of this run is scoped to it
    return None  # run the AI pipeline
PLAIN ENGLISH

Look for something shaped like an alert ID (e.g. ALR-A2-001) in your message.

If found, keep the ID, in capital letters.

Get the list of alerts this chat has already investigated.

If this alert is on that list and you didn't say "rerun"…

…reply "already investigated" and show its approval queue…

…instead of paying for a second full AI run.

Cut the ID at the dashes: the middle part, "A2", is the scenario.

If no such scenario exists in the lab data…

…say "unknown alert" and stop.

Write the alert ID on the shared notepad (the "state") for later agents.

Also note the scenario, so every agent reads only that scenario's data.

Returning "nothing" means "carry on and start the AI agents".

💡
Not everything should be AI

Reading an ID from text is a job for a simple rule. It's instant, free and never wrong. Good AI systems keep AI for judgment calls and use plain code for everything predictable. When you ask an AI to build something, say so explicitly: "do this in plain code, not with the model".
